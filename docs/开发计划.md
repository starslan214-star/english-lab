# English Lab 详细开发计划

> 版本：2026-09-20 · 策略：**先做网页版，在现有代码上演进，不推倒重来**
>
> 配套文档：`docs/资源与数据源清单.md`（词库/词典/外刊/书籍调研结果）

---

## 一、现状盘点：你不是从零开始

当前仓库已经是一个能跑的 MVP（PWA + 自包含 Node 服务器 + Cloudflare Worker 版本）。按「English Learning OS」八模块对照：

| 模块 | 已有 | 缺口 |
|---|---|---|
| 🏠 Today | 每日任务（复习5/学5/读1）+ XP | 无 Streak 连续天数、无学习时长统计、任务量写死 |
| 📚 Words | 5,765 词（WordTyper 四六级 + 16 个精选场景词）、中文默认隐藏、筛选/分页/朗读 | 词库缺「Daily / Testing / AI」三路线标注（只有 CET4/6 标签）；学习是顺序翻页，不是「今日待办队列」 |
| 复习 | `review-core.js` 简化间隔复习（again/hard/good/easy → 下次间隔） | 不是 FSRS；且 `app.js` 里还有第二套内联复习逻辑，两套并存 |
| 📰 Reading | 3 篇原创 A1 分级文章（点击查词 + 1 题 Quiz + 打印 PDF）；新闻页读 Google AI Blog + Selenium Blog 的标题/日期/原文链接（20 分钟刷新） | 无 RSS 入库管道、无 AI 降级改写、无文章内 AI Tutor、无难度评估 |
| 🎮 Game | Bug Hunter 固定 5 题 + XP | 只有 1 种游戏、题库写死、无关卡地图 |
| 🔍 Dictionary | ECDICT 派生离线词条（音标+中文）+ Free Dictionary API 英英 + 百度翻译（服务端验证凭据、AES-GCM 加密 Cookie）+ DeepSeek AI 补充 | 无搭配/词组/同反义词源；无更多英英词典备选 |
| 🤖 AI Tutor | DeepSeek 助教（用户自带 Key、加密会话 Cookie、非思考模式） | 绑死 DeepSeek；无 Provider Adapter；无预设能力（故事生成/语法拆解/自动测验/日总结） |
| 📖 Notebook | 收藏词/句 + 自己的注释 + Markdown 导出 | 与文章、复习的闭环不完整 |
| 📊 Log/Progress | 日志 Markdown 预览/下载 + JSON 备份导入导出 | 无自动生成、无周报、无图表 |
| 🔧 基建 | PWA（manifest + sw）、自包含服务器、Worker 代理、词库构建脚本、中英 i18n、check 脚本 | 数据全在 localStorage 单个 key（有 5MB 容量上限风险） |

**动手前必须知道的三个事实：**

1. `dist/server/index.js`（608KB）是把整个前端内联后的**生成物**，只能由构建脚本重新生成，不能手改；
2. 复习算法存在**两套实现**（`review-core.js` 与 `app.js` 内联版），行为不一致，阶段 0 必须统一；
3. 所有学习数据存在 localStorage 的 `english-lab-state-v1` 一个 key 里，词库涨到上万词 + 文章库后必然撞 5MB 上限。

## 三、关键技术决策

### 决策 1：不迁移 Next.js + Supabase + PostgreSQL

原计划里的这套栈是为「多用户产品」设计的。你的实际场景是：单人使用、本地优先、iCloud 文件夹里自建自用。迁移的代价（新框架学习、数据库运维、部署）远大于收益。

**结论：保持现有架构（vanilla JS 前端 + 自包含 Node 服务器 + Cloudflare Worker 可选部署），只做结构整理。** 未来若确实需要多设备同步，再评估 Supabase 作为可选同步层，数据层先按可同步设计（见决策 2）。

### 决策 2：学习数据 localStorage → IndexedDB（Dexie.js）

- localStorage 单 key 5MB 上限，存不下文章库和成长中的词库；
- 用 [Dexie](https://dexie.org/)（零依赖、成熟稳定）建表，首次启动自动从旧 `english-lab-state-v1` 迁移；
- 保留现有 JSON 备份/导入功能，备份格式升级为 v2（带 `schemaVersion` 字段），旧备份可导入。

### 决策 3：SRS 换成 FSRS（ts-fsrs）

现有简化算法是 SM-2 变体，对「零基础、复习间隔短」场景误差大。[ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs)（MIT，open-spaced-repetition 官方社区维护）是现成实现：

- `Rating` 同样是 Again/Hard/Good/Easy 四键，UI 不用改；
- 迁移策略（渐进，不丢数据）：旧记录打 `legacy` 标记继续按旧间隔到期；用户下一次评分时转换初始化 FSRS 参数（stability ≈ 旧 interval，difficulty 由历史 lapses 估算）；
- 保留 `scripts/check-review.mjs`，新增用例：同一张卡 FSRS 连续 30 次调度的合理性断言。

### 决策 4：AI Provider Adapter（OpenAI-compatible 统一接口）

现在绑死 DeepSeek。改为设置页可配 `Base URL / API Key / Model / Temperature`，兼容所有 OpenAI 格式端点（DeepSeek、Kimi、GLM、本地 Ollama 等）。网站内部只调用六个语义方法：

```js
ai.explain()    ai.translate()   ai.grammarBreakdown()
ai.quiz()       ai.story()       ai.summarizeDay()
```

密钥安全沿用现有方案：服务端验证 + AES-GCM 加密 HttpOnly Cookie，前端永不接触明文 Key。

### 决策 5：词典四层结构（由快到慢、由免费到付费）

1. **离线层**：ECDICT 派生词条（已有，音标+中文释义，离线可用）；
2. **英英层**：Free Dictionary API（已有）+ 补充 Merriam-Webster 免费 API（英英释义+同反义词，需申请免费 key）；
3. **翻译层**：百度翻译（已有，覆盖词组/句子）；
4. **AI 层**：DeepSeek 按需生成搭配、用法、辨析（已有，明确标注 AI 生成）。

牛津付费 API 暂不接（成本高，收益低），Oxford Learner's 免费网页跳转保留。

### 决策 6：版权红线（详细版见资源文档）

- RSS 来源**只存标题 + 摘要（≤150字）+ 日期 + 原文链接**，全文不落库、不整页转载；
- AI 降级改写**只允许用于许可允许的语料**：VOA Learning English（美国联邦政府作品，公有领域）、pytest 文档（CC0）、12factor / Selenium 文档（CC BY）、Simple English Wikipedia / MDN（CC BY-SA，附署名+修改声明）；
- 禁止作为改写底稿：Google SRE Book（CC BY-NC-**ND**）及一切普通版权书/商业词典。

## 五、阶段 2：V2 外刊阅读引擎（第 4-6 周）

### 采集管道（服务端定时，沿用 worker/Node 服务器）

```text
RSS 源列表（见资源文档「推荐订阅清单」）
  → 每 2-4 小时抓取：标题 + 摘要 + 日期 + 链接（全文不落库）
  → 去重（URL + 标题相似度）
  → AI 评分：topic 分类 / 难度估计 / usefulness(1-10)（批量、低频、便宜模型）
  → 入库（IndexedDB articles 表）
```

首批源（已逐个实测抓取，详见资源文档）：VOA Learning English（公有领域，全文改写重点源）、Simple English Wikipedia（CC BY-SA 改写底稿）、News in Levels（自带 1/2/3 级）、DEV.to testing/ai 标签、Ministry of Testing（feed 是 `/contents/rss`）、Hacker News Algolia API；Selenium/Playwright 用 GitHub Releases Atom 替代（官方博客实测无 RSS）。注意 VOA feed 条目顺序陈旧，入库时按 pubDate 自行排序去重。

### 阅读页改造

- 文章列表：按 topic（Testing / AI / CS / Daily）+ 难度（预估 CEFR）筛选，默认推荐「今天最适合你的 3 篇」；
- 文章详情：摘要 + 原文链接（外站阅读）；学习版正文（AI 改写，见下）内嵌点击查词；
- AI 降级改写：对**合法语料**（VOA / CC0 / CC BY / CC BY-SA，含署名+修改声明）生成 A1/A2/B1 三个版本缓存；对普通版权源只做「AI 讲解摘要」（不逐句改写）；
- 文章页 AI Tutor：Explain paragraph / Grammar / Quiz / Ask me questions（复用 1.4 的能力）；
- 生词闭环：文章内点击查词 → 一键加入词库 → 进入 FSRS 队列 → 一周后 AI 用这批词再生成新故事（闭环闭合）。

### 学习版 PDF

升级现有打印样式为「English Learning Sheet」：Easy Reading + Key Vocabulary + Grammar 点 + 3 道练习 + Notes 空行 + 来源署名与许可声明。纯 CSS `@media print`，不引 PDF 库。

## 七、阶段 4：V4 本地 Agent + Obsidian（第 9-10 周）

```text
浏览器端「导出今日数据」按钮（JSON）→ ~/English Lab/data/today.json
        ↓
scripts/agent.mjs（Node，launchd/cron 每晚 22:00）
        ↓
读取导出 + 可选调用你的 AI Provider
        ↓
写入 Obsidian vault（路径在配置文件里）：
  English/
  ├── Dashboard.md            （自动重写：本周统计 + 到期预测）
  ├── Daily/2026-09-20.md     （已有 logText() 模板，升级为完整版）
  ├── Vocabulary/Software Testing.md   （按 track 追加生词）
  └── Reading/                 （已读文章记录 + AI 摘要）
```

要点：
- Agent 只读导出文件、只写 Markdown，**不反向写浏览器数据**（数据主权永远在前端）；
- 周报：每周日生成 `Weekly/2026-W38.md`（新词数曲线、正确率、三类路线进度）；
- iCloud 注意：Obsidian vault 若也在 iCloud，写入用原子写（先写临时文件再 rename），避免同步冲突。

## 八、阶段 5（可选）：V5 浏览器插件

Manifest V3 划词插件：选中文本 → 弹窗显示（离线 ECDICT 释义 + 英英 + 中文）→ `+ Add Vocabulary` 把词通过本地服务器接口（`POST /api/words`，仅监听 127.0.0.1）写入词库 → 当晚进复习队列。插件本身只是词典 UI + 一个 POST，两天工作量。

## 九、数据模型 v2（IndexedDB / Dexie 表）

```text
words          { word, ipa, zh, def?, track: [daily|testing|ai], levels: [cet4|cet6|...], scene?, source }
cards          { word, fsrs: {stability, difficulty, due, reps, lapses, state}, legacy?: {...}, addedAt }
reviews_log    { word, rating, at }                      ← 供统计与误操作回溯
articles       { id, source, url, title, excerpt, publishedAt, topic, levelEst, usefulness,
                 versions: { a1?, a2?, b1? }, license, attribution, fetchedAt }
sentences      { text, note, words: [], from, at }       ← 现有 notebook
daily_stats    { date, learnCount, reviewCount, readCount, minutes, xp }
settings       { aiProvider, dictionaries, quests: {reviewN, newN}, ... }
```

设计原则：每张表都能单独导出成 JSON；备份 = 全表 dump + `schemaVersion`。
